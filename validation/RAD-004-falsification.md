## 1. Repository reality (confirmed in code/data, not README claims)

Radar is **not a running system**. On disk it is three things:

- **A specification** (`docs/`: product-contract, signal-model, decision-system,
  ux, design) — internally coherent and unusually disciplined.
- **A manual instrument** — one Excel workbook
  (`prototype/output/tourism_signal_radar_lean_prototype.xlsx`) generated by
  `prototype/build_lean_prototype.mjs`. No automation, no scraping, no AI. This
  is "the actual Phase-0 tool" (`README.md:35`).
- **Six hand-entered signals** (`validation/signals.csv`) plus a six-row human
  evaluation log (`validation/validation-log.csv`).

The Next.js/Cloudflare spike in `spikes/web/` is explicitly **FROZEN**, "must
not be developed against," and "already drifts from the spec" (`FROZEN.md`). It
is not evidence of a built product.

What Radar actually *is*, structurally (verified in `docs/decision-system.md`):

- **Four epistemic layers** kept visibly separate: Source fact → Interpretation
  → Recommendation → Human decision. AI may draft the middle two; **never** the
  Source-fact layer, **never** the human decision.
- **Evidence quality** = deterministic HIGH/MED/LOW rubric with mandatory
  rationale. Explicit ban on 0–100 scores and weighted composites
  (`AGENTS.md:28`).
- **Contradiction as a first-class typed relationship**
  (Supports/Contradicts/Contextualizes), with an independence check and an
  explicit rule: *do not balance source counts.*
- **Bounded THE MOVE** with a "move lint" that rejects vague verbs, "read the
  source," and moves with no completion trigger.
- **Append-only history**; past claims/decisions never silently rewritten.

## 2. Comparator limitation (the binding evidence gap)

The "Tourism Mobility Intelligence System" **does not exist in this repository
in any inspectable form.** It appears only as prose inside RAD-004's own
`signal_claim` (`validation/signals.csv`): *"an existing tourism mobility
intelligence platform … turns tourism and mobility data into actionable findings
through GenAI."* There is no code, schema, output, or dataset for it.

The only competitor artifact actually written in-repo is a one-line reference to
**Feedly Market Intelligence** (`docs/product-contract.md:249`), self-flagged as
"the strongest warning that 'AI signal detection' alone is not differentiation."

This gate therefore assesses Radar against that **capability class** (GenAI
insight / synthesis generators) and treats the specific named platform as
**missing evidence, not invented evidence.** No comparator output was
fabricated. This limitation is the primary reason confidence is LOW.

## 3. Test question

*"Spain's 2026 heat/drought/wildfire conditions are intensifying. Should fire
risk be treated as a dynamic management constraint on a specific tourism asset,
or remain background context?"* — the real decision behind RAD-003
(`project = SNTO/TFM`, 3 sources, contradiction flagged). Chosen because it is a
real tourism decision with multiple sources and a live contradiction: the exact
case where both systems should earn their keep.

## 4. Side-by-side comparison (Radar-class model vs. GenAI-insight class)

| Dimension | GenAI insight generator (Feedly-class) | Radar (as specified) | Real gap? |
|---|---|---|---|
| Multi-source synthesis | Yes — clustering/trend synthesis is its core strength | Many-to-many Source↔Signal, typed | **No net advantage** — both synthesize |
| Contradiction detection | Smoothed into generated prose; not persisted | First-class, typed, independence-checked, persisted | **Yes — structural** |
| Evidence provenance | Model output *is* the insight; citations optional/derivative | Every claim → retrievable Source; AI output never a Source; unverifiable → quarantined | **Yes — structural** |
| Signal/interpretation separation | Collapsed into one fluent narrative | Four enforced epistemic layers | **Yes — structural** |
| Reject weak signals | Optimizes for *more* insights | LOW→DISMISS, "deserves no move," P3, move-lint | **Yes — workflow** |
| Decision usefulness | High-volume "why it matters" | Bounded, human-owned disposition | Contested (see §6) |
| THE MOVE quality | Generic closing advice | Specific & bounded ("compare on two known sites *before* changing pipeline; do not change thresholds") | **Yes — workflow** |
| Changes a human decision | Unknown | **4 of 6 "useful" moves were *ignored*** | **Advantage NOT shown** |

## 5. Claimed-differentiation audit

- Multi-source synthesis → **NOT DEMONSTRATED** (parity with competitor class;
  no unique lift shown).
- First-class contradiction handling → **STRUCTURAL DIFFERENTIATION** (design) /
  **NOT DEMONSTRATED** (outcome — the CSV flags `contradiction_present=yes` but
  records neither the contradicting sources nor how it changed a decision).
- Evidence provenance / quarantine → **EVIDENCE DIFFERENTIATION** — genuinely
  absent from a class where the generated text is the deliverable.
- Four-layer signal/interpretation separation → **STRUCTURAL DIFFERENTIATION**.
- Reject weak signals + move-lint → **WORKFLOW DIFFERENTIATION**.
- Bounded THE MOVE specificity → **WORKFLOW DIFFERENTIATION** (not prose polish;
  the boundaries are operational).
- The frozen web spike / UI → **ONLY UI**, and drifts from spec — zero gate
  weight.

## 6. Strongest falsification evidence

Statement under test: *"Radar adds no material decision capability beyond the
existing Tourism Mobility Intelligence System."*

1. **Useful but inert.** `validation-log.csv`: `the_move_useful = yes` for all 6,
   yet `human_decision = ignored` for **4 of 6**. A move judged useful and then
   not acted on is precisely the "templated closing sentence" failure
   `VALIDATION.md` Q2 says should **kill**.
2. **The two "act" rows are self-referential.** The only acted-on moves are
   **RAD-004** (this falsification task) and **RAD-006** (a self-audit of a
   *different* project's architecture). **Zero** operational tourism decisions
   were changed. So far the tool generates work about itself.
3. **The comparator was never run.** RAD-004's own THE MOVE was "run one bounded
   competitive falsification … in Radar and the Tourism Mobility Intelligence
   System." It cannot be executed as written — the second system is
   inaccessible. The central differentiation claim is **asserted, never tested.**
4. **n = 6, single author, no built product.** This is a spec and a spreadsheet,
   not repeatable capability.

## 7. Strongest survival evidence

1. The contradiction/provenance/separation model is a **real epistemic
   structure, not LLM prose.** A GenAI insight generator that emits a fluent
   paragraph *cannot*, by construction, hand you a persisted, typed,
   independence-checked contradiction object tied to retrievable sources with the
   model explicitly barred from being evidence. That is a category difference,
   not a formatting difference.
2. THE MOVE examples are **operationally bounded** in a way generic "insights"
   are not: *"do not change thresholds or model logic," "test on a single
   existing asset; do not build a feature if it does not [change the
   decision]."* This is decision hygiene a summarizer does not produce.
3. The system **can say "no move"** and reject weak signals — the opposite of
   engagement-optimized insight feeds.

## 8. Verdict

**SURVIVE WITH CONDITION.**

The differentiation is **not** mainly interface or prose — the
contradiction/provenance/separation structure is genuinely absent from the
competitor class, so a clean FAIL is not honest. But it is **not demonstrated to
change a real decision**: 4/6 useful-but-ignored, the 2 acted-on are meta-tasks,
and the head-to-head was never run because the comparator is inaccessible. So a
clean SURVIVE is not earned either. Potentially real differentiation; one
decisive experiment still owed.

## 9. Confidence

**LOW.** Binding reasons: the comparator cannot be inspected (half the gate is
missing); n=6; single author; decision-impact evidence is negative-leaning (4/6
ignored). Confidence rises to MEDIUM only when the §10 experiment runs against an
*actually accessible* competitor.

## 10. The single next experiment

Take **one real tourism decision you must actually make in the next two weeks**
(RAD-003's fire-risk constraint is the strongest candidate — not another
meta/self-audit signal). **Pre-register** the disposition a plain GenAI summary
of the same sources would push you toward. Then run those same sources through
the Radar workbook.

- **Discriminating test:** does Radar's first-class contradiction + provenance
  flip or materially qualify the disposition versus the GenAI summary?
- **Success criterion:** Radar materially flips or defensibly bounds the
  disposition → differentiation is real.
- **Failure criterion:** materially identical disposition → the structure is
  inert → **FAIL**.

One decision, one comparison, falsifiable, cheap.
